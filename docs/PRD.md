# 樂透統計與選號工具 PRD

版本:v0.1(草案)　日期:2026-10-12

## 1. 目標與定位

針對台灣彩券三種遊戲 **今彩539、大樂透、威力彩**,提供「開獎資料管理 → 歷史查詢 → 統計分析 → 依統計組合選號」的個人工具。

**定位聲明(需在產品內明確顯示)**:樂透每期為獨立隨機事件,冷熱、遺漏、連莊等統計對下一期無預測力。本工具為描述歷史與輔助選號的娛樂用途,不保證提高中獎機率。產品內提供「回測」與「卡方檢定」,讓使用者自行驗證這一點。

## 2. 範圍

| 項目 | 內容 |
|---|---|
| 遊戲 | 今彩539(5 個號碼,1-39)、大樂透(6 個號碼 1-49 + 特別號)、威力彩(第一區 6 個 1-38 + 第二區 1-8) |
| 實作順序 | 先做 539,再擴充大樂透、威力彩(見第 8 節) |
| 資料起點 | 539、大樂透:2007-01;威力彩:2008-01-24(發行日) |
| 不在範圍 | 賓果、3星彩、4星彩、樂合彩等其他遊戲;自動購票/下單;多人帳號 |

## 3. 現況資料

- 原始資料:`history/` 底下各年份 CSV(民國年與西元年資料夾並存,欄位格式不一)。
- 已整合:`今彩539.json`(5,981 期)、`大樂透.json`(2,174 期)、`威力彩.json`(1,950 期),由 `build_json.py` 產生。
- 單期資料結構:

```json
{"period":"103000001","date":"2014-01-03","sales":146792850,"bets":2935857,"prize":80736067,"numbers":[11,18,20,21,35,37],"special":8}
```
`special` 在大樂透為特別號、威力彩為第二區;539 無此欄位。

**統計範圍參數(所有統計共用)**:遊戲、範圍 = 歷史全部 / 最近 N 期 / 日期區間。「近一年」改以固定期數表達(因 539 每週 6 期、大樂透與威力彩每週 2 期),預設值:539 = 300 期、大樂透 = 100 期、威力彩 = 100 期,可調。

### F4. 依統計組合產生號碼

使用者以「統計項目 × 取幾個」的方式組合配方,系統產出一組(或多組)推薦號碼。

#### 4.1 配方語法

配方 = 若干「條目」,每個條目為 `(統計來源, 取幾個)`。

範例:
- `最多次 ×2 + 最少次 ×3`
- `最多次 ×2 + 最少次 ×2 + 連莊 ×1`
- `遺漏最久 ×2 + 近10期熱號 ×2 + 重號 ×1`

#### 4.2 可用的統計來源(條目選單)

| 來源 | 取號方式 |
|---|---|
| 最多次 | 範圍內出現次數由高到低 |
| 最少次 | 範圍內出現次數由低到高 |
| 連莊 | 目前連莊期數由長到短 |
| 遺漏最久 | 目前遺漏由長到短 |
| 遺漏比值高 | S6 比值由高到低 |
| 上期重號 | 從最近一期號碼中取 |
| 近 N 期熱號 | 近 N 期次數最高 |
| 鄰號 | 最近一期號碼的前後號 |
| 隨機 | 從剩餘號碼隨機補 |

#### 4.3 規則與行為

| 編號 | 需求 | 優先 |
|---|---|---|
| F4.1 | 條目總數必須等於該遊戲所需號碼數(539 為 5、大樂透與威力彩第一區為 6);不足時可選「剩餘以隨機補滿」 | P0 |
| F4.2 | **去重**:條目按填寫順序取號,已被取走的號碼自動跳過,取下一個 | P0 |
| F4.3 | **同分處理**:排名同分時可選「隨機」或「較小號優先」,預設隨機 | P0 |
| F4.4 | 每個條目可自訂統計範圍(例如熱號用近 20 期,最少次用歷史全部);未設定則沿用全域範圍 | P1 |
| F4.5 | 威力彩、大樂透的特別號/第二區:以獨立的一行配方設定,預設隨機或取該區冷/熱號 | P1 |
| F4.6 | 可一次產生多組(例如 5 組),各組同分隨機結果不同;多組之間可選「彼此不重複」 | P1 |
| F4.7 | 結果顯示每個號碼由哪個條目選中,讓人看得懂來源 | P0 |
| F4.8 | 可儲存常用配方並命名,之後一鍵套用 | P1 |
| F4.9 | 配方可附加「條件過濾」,例如總和落在歷史 80% 區間、奇偶比不要 0:5 或 5:0,不符時重新抽 | P2 |
| F4.10 | **固定號碼**:使用者可指定一定要有的號碼,配方只補剩下的(2026-10-12 新增) | P0 |
| F4.11 | **增加號碼(包牌)**:每注 N 個號碼時可多選 1~2 個,系統把所有 C(N+k, N) 組合展開並顯示注數與金額;威力彩第二區可選「全部 8 個」(例:第一區 +1 號、第二區全包 = 7×8 = 56 注)。大樂透特別號為開獎附加號,投注時不選,故不適用(2026-10-12 新增) | P0 |

### F5. 其他選號推薦方式

以下為建議新增的「一鍵策略」,每個都可單獨使用,也可成為 F4 配方的條目來源。

| 編號 | 策略 | 做法 | 優先 |
|---|---|---|---|
| F5.1a | **均衡型** | 從歷史最常見的結構中隨機挑:奇偶比、大小比、和值區間、區段分布都取歷史眾數附近,再隨機填號。目的是避開極端組合,不是提高中獎率 | P0 |
| F5.1b | **冷熱混合型** | 熱號、溫號、冷號按固定比例各取若干 | P1 |
| F5.1c | **回補型** | 偏好目前遺漏 ÷ 平均間隔比值高的號碼 | P1 |
| F5.1d | **追熱型** | 偏好近 N 期次數最高的號碼 | P1 |
| F5.1e | **重號 + 鄰號型** | 取上期 1 個重號,再取上期號碼的鄰號 | P2 |
| F5.1f | **配對型** | 先選一個熱號,再補歷史上最常與它同期出現的號碼 | P2 |
| F5.1g | **加權隨機** | 以歷史頻率或遺漏為權重隨機抽樣,每次結果不同 | P1 |
| F5.1h | **避熱門型** | 避開生日號碼(1-31)與常見規律(連號、等差),只在號碼多於 31 的遊戲上有意義。**出發點是:中獎機率不變,但若中獎可減少與他人分獎的機會**(大樂透、威力彩為彩金均分制) | P1 |
| F5.1i | **純隨機(電腦選號)** | 作為基準線 | P0 |
| F5.2 | **多注覆蓋** | 產生 N 注,盡量讓號碼分散覆蓋範圍、減少重複 | P2 |
| F5.3 | **策略回測** | 對任一策略(含 F4 配方),在指定歷史區間模擬「每期用當期以前的資料產生推薦,與實際開獎比對」,統計平均命中個數、各中獎等級次數,並與純隨機基準比較;附信賴區間或顯著性結論 | P1 |

說明:F5.3 是這個工具的核心價值之一,它能誠實地告訴使用者各種策略是否優於隨機(預期結論多半是「沒有」)。回測時必須嚴格避免用到未來資料。

## 6. 資料模型

三個遊戲各一份 JSON,維持第 3 節的結構。衍生資料(遺漏表、頻率表等)於執行時計算,不另外持久化,避免與原始資料不同步。

配方儲存格式(F4.8)示意:

```json
{
  "name": "冷熱各半",
  "game": "539",
  "scope": {"type": "last_n", "n": 300},
  "items": [
    {"source": "most_drawn", "count": 2},
    {"source": "least_drawn", "count": 2, "scope": {"type": "all"}},
    {"source": "current_streak", "count": 1}
  ],
  "tie_break": "random",
  "fill_random": false
}
```

## 7. 介面(分頁式單頁網站,比照輕盈計畫)

頂層分頁,頂端另有遊戲切換(539 / 大樂透 / 威力彩),所有分頁共用同一個遊戲選擇與統計範圍:

1. **開獎**:近 N 期列表、更新資料(匯入/手動輸入)、更新報告。
2. **統計**:範圍選擇列,下方以子分頁或區塊呈現各統計(表格 + 圖表)。
3. **選號**:配方編輯器(新增條目、設定取幾個,即時顯示「已選 X / 需要 Y」)、一鍵策略、產生結果、儲存配方。
4. **回測**:選策略與區間,顯示與隨機基準的對照圖表。
5. **說明**:定位聲明、資料出處、各統計的白話解釋。

介面需能在手機上使用(朋友多半用手機開)。

## 10. 部署與架構

### 10.1 架構原則(參考輕盈計畫 Lighten2)

輕盈計畫的做法是:純前端、無建置步驟(直接 `index.html` + 原生 JS 模組)、資料放 `data/*.json`、`tools/` 放 Node 產生與檢查腳本、GitHub Actions 每次 push 跑檢查、`docs/` 放 PRD 與決策紀錄。本專案沿用同樣的風格,讓兩個專案維護方式一致:

- **前端**:原生 JS(ES 模組)+ 單頁分頁式介面,不用框架、不需要 build。
- **邏輯分層**:`js/core`(共用工具)、`js/data`(讀資料、本機儲存)、`js/engine`(統計、選號、回測,純函式,不碰畫面)、`js/ui`(各分頁)。統計與選號全放在 `engine`,可用 Node 直接跑測試。
- **後端工具**:只有「資料準備」,不在網站上執行。沿用現有 Python `build_json.py`(CSV → JSON),新增 `fetch_latest.py`(抓最新期數)。若日後想與輕盈計畫統一,可改寫成 Node,但非必要。
- **使用者本機資料**(手動輸入的期數、儲存的配方):存在瀏覽器本機,可匯出/匯入 JSON(比照輕盈計畫的備份機制)。

### 10.2 目錄結構

```
lotto/
├─ index.html
├─ css/
├─ js/
│   ├─ core/        共用工具、遊戲規格設定(539 / 大樂透 / 威力彩)
│   ├─ data/        載入 data/*.json、本機儲存、匯入匯出
│   ├─ engine/      stats/、recipes/(選號)、backtest/ ,純函式
│   └─ ui/          各分頁
├─ data/            今彩539.json、大樂透.json、威力彩.json
├─ history/         原始 CSV(全部保留,依年份)
├─ tools/           build_json.py、fetch_latest.py、檢查腳本(資料驗證、引擎測試)
├─ docs/            PRD.md(本文件)、decisions.md、資料出處說明
├─ README.md
└─ .github/workflows/
     ├─ check.yml          push 時:驗證 data/*.json、跑引擎測試
     ├─ update-data.yml    開獎日定時抓最新期數 → 驗證 → 更新 data/ → 自動 commit(M4)
     └─ pages.yml          發布到 GitHub Pages
```

### 10.3 對需求的影響

| 需求 | 靜態網站下的做法 |
|---|---|
| F1.3 自動更新 | 由 GitHub Actions 排程執行,抓取、驗證通過才 commit 回 repo,網站隨之更新。在 Actions 內抓取也避開瀏覽器的跨網域(CORS)限制 |
| F1.1 手動輸入 / F1.2 匯入 | 網頁無法寫回 repo,輸入的資料只存在**該使用者的瀏覽器**,畫面標示為「本機資料」,可匯出。要正式納入共用資料需由維護者改 repo 的 JSON |
| F4.8 配方儲存 | 存在使用者自己的瀏覽器,可匯出/匯入 JSON 分享給朋友 |
| F5.3 回測 | 在瀏覽器執行,用 Web Worker 避免畫面卡住 |
| 備份(F1.5) | 以 git 歷史為備份;自動更新驗證失敗時不 commit |

### 10.4 免費部署選項

| 平台 | 說明 |
|---|---|
| GitHub Pages(首選) | 與 repo 同處,push 後自動發布。網址為 `https://<帳號>.github.io/<repo>/` |
| Cloudflare Pages / Netlify / Vercel | 連結同一個 repo 即可,因為沒有 build 步驟,部署設定只需指定根目錄;可綁自訂網域 |

注意:免費版 GitHub Pages 需要 **public repo**,repo 內所有內容都會公開。

### 10.5 公開前檢查

- repo 內不放帳號、金鑰、個人資料;自動抓取如需金鑰,用 GitHub Secrets。
- 開獎資料來源須註明出處,並確認其使用條款是否允許轉載整理。
- 網站固定顯示免責聲明(第 1 節)。
- 抓取頻率要克制(僅開獎日抓一兩次),避免對來源網站造成負擔。
- 加上 `.gitignore`、`README.md`(用途、資料來源、使用方式)與授權條款。
